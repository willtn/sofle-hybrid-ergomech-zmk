# AGENTS.md

## What this repo is

ZMK firmware **user config** for a **Sofle v2 Hybrid** split keyboard (ErgoMech, rev5 PCB).
This is a personal **fork** of the seller's repo (https://github.com/ergomechstore/sofle-hybrid-ergomech).

There is no application code here — only declarative config (Devicetree, Kconfig, keymaps, YAML).
Firmware is built in GitHub Actions using the upstream ZMK workflow; there is no local build/test loop.

## The one thing I actually edit: the keymap

My goal in this repo is to **personalize the keymap**. The rest of the config is tailored to the
keyboard hardware and should be left alone unless there is a specific reason.

- **Edit this file:** `config/sofle_ergomech.keymap`
  - It is the canonical keymap: rendered to the SVG, editable in the online keymap editor, and it
    overrides the shield's default keymap at build time.
- **Leave these alone (hardware/shield definition shipped by the seller):**
  - `boards/shields/sofle_ergomech/**` — Devicetree (`.dtsi`, `.overlay`), Kconfig (`Kconfig.*`),
    and `.conf` files. There is a second `sofle_ergomech.keymap` in here; it's the shipped default
    and is **not** the file I personalize.
  - `zephyr/module.yml`, `config/west.yml` (pins ZMK `v0.3`).

> Note: `config/` and `boards/shields/sofle_ergomech/` contain parallel copies of `.keymap`/`.conf`
> that have already drifted. For keymap personalization, only `config/sofle_ergomech.keymap` matters.
> Do not try to "sync" the two unless explicitly asked.

## Keymap structure (`config/sofle_ergomech.keymap`)

- Layers: `BASE 0`, `LOWER 1`, `RAISE 2`, `ADJUST 3` (ADJUST is conditional: LOWER + RAISE).
- This is a 6×4 + 5 split. Each layer's `bindings` block is laid out as rows; the **last row** holds
  the right-side **5-way switch** keys — keep the correct number of entries on that row or it breaks.
- The encoder push-button is intentionally placed at the **bottom-left** of the textual keymap to
  support the visual layout editor. Remember this when editing manually.
- Keep the ASCII layout comment above each layer in sync with the bindings, and keep column
  indentation aligned for readability.
- Preserve the MIT `SPDX-License-Identifier` / copyright header at the top of the file.

## Build & release (CI only)

- `.github/workflows/build.yml` builds via `zmkfirmware/zmk/.../build-user-config.yml@v0.3`.
- Build matrix is in `build.yaml` (shields `sofle_ergomech_left`, `sofle_ergomech_right`,
  `settings_reset`; board `nice_nano_v2`; left side enables ZMK Studio).
- Pushes to `sofle_hybrid_rgb_rev5` (the active rev5 branch) cut a dated firmware release with `.uf2`
  artifacts. `master`/`Default` is the legacy PCB — not used here.
- `.github/workflows/keymap_drawer.yaml` re-renders `keymap-drawer/sofle_ergomech.svg` whenever
  `config/*.keymap` changes.

## Keymap personalization workflow

1. Edit `config/sofle_ergomech.keymap` (manually, or via the
   [ZMK keymap editor](https://nickcoutsos.github.io/keymap-editor) — this repo's `config/sofle_ergomech.json`
   is set up for it).
2. Push to `sofle_hybrid_rgb_rev5`. GitHub Actions builds firmware and cuts a dated release with
   `.uf2` files (`sofle_ergomech_left`, `sofle_ergomech_right`, `settings_reset`).
3. Flash the new `.uf2` files to each Nice!Nano (double-tap BOOT to enter bootloader mode).
4. Optionally use [ZMK Studio](https://zmk.studio/) for live remapping over USB — unlock via
   `&studio_unlock` on the lower layer (top-left key). Bluetooth remapping is not supported.

Do **not** edit `boards/shields/sofle_ergomech/sofle_ergomech.keymap` or shield `.conf` files when
personalizing the keymap.

## Verifying changes

There is no test suite. After editing the keymap:

- Make sure the Devicetree syntax is valid (matched braces, `<>`, trailing `;`).
- Make sure every row has the expected key count (especially the 5-way switch row).
- Confirm intent against the rendered `keymap-drawer/sofle_ergomech.svg` (regenerated by CI).
- The real check is a green ZMK build in GitHub Actions.
